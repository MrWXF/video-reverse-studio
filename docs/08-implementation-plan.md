## 3. T1 设计

### 3.1 目标

在上传视频、正式分析之前，让用户看到：

- 预计拆解多少个镜头。
- 预计消耗多少 token。
- 按当前模型单价估算的费用。
- 当前估算是否可计费、是否包含 ASR 和视频生成费用。
- 可操作的节省建议。

分析完成后继续展示现有实际 token 用量与费用。

### 3.2 API

`POST /api/projects/estimate-cost`

```json
{
  "video_duration": 60,
  "estimated_shots": 18
}
```

`estimated_shots` 可省略；省略时按配置的平均镜头时长估算，并受 `MAX_SHOTS` 上限约束。

响应包含：

- `estimated_shots`、`shot_count_source`
- `cost.prompt_tokens`、`cost.completion_tokens`、`cost.total_tokens`
- `cost.vision_cost`、`cost.text_cost`、`cost.total_cost`
- `cost.priced`、`cost.estimated_cost`、`cost.note`
- `suggestions`
- `assumptions`

### 3.3 边界

- 估算是规划值，不是供应商账单。
- 当前只估算视频逆向分析的视觉模型调用。
- ASR 若启用，按供应商单独计费，不混入模型 token 估算。
- 真实视频生成费用在 T6 接入后单独计算。
- Mock 模式下即使配置单价，也明确提示不会产生供应商费用。

## 4. T1 验收

- API 可返回按时长推断和手动指定镜头数两种估算。
- 未配置单价时金额为空，并给出配置提示。
- 镜头数超过 `MAX_SHOTS` 时自动封顶并提示。
- 上传区在读取到视频时长后自动显示预估。
- 分析后仍展示实际成本。
- 后端、前端语法和回归测试全部通过。
