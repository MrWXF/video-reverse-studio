## 1. 执行原则

- 先无外部依赖、可直接验收的能力，再处理供应商接入和平台化改造。
- 每项任务按“设计 → 开发 → 测试 → 验收”完成，不跨任务混改。
- 真实视频生成费用、供应商账单和法律用途结论，不在未验证前对外承诺。

## 3. T1 设计

### 3.1 目标

在上传视频、正式分析之前，让用户看到：

- 预计拆解多少个镜头。
- 预计消耗多少 token。
- 按当前模型单价估算的费用。
- 当前估算是否可计费、是否包含 ASR 和视频生成费用。
- 可操作的节省建议。

分析完成后继续展示现有实际 token 用量与费用。

### 3.2 API

`POST /api/projects/estimate-cost`

```json
{
  "video_duration": 60,
  "estimated_shots": 18
}
```

`estimated_shots` 可省略；省略时按配置的平均镜头时长估算，并受 `MAX_SHOTS` 上限约束。

响应包含：

- `estimated_shots`、`shot_count_source`
- `cost.prompt_tokens`、`cost.completion_tokens`、`cost.total_tokens`
- `cost.vision_cost`、`cost.text_cost`、`cost.total_cost`
- `cost.priced`、`cost.estimated_cost`、`cost.note`
- `suggestions`
- `assumptions`

### 3.3 边界

- 估算是规划值，不是供应商账单。
- 当前只估算视频逆向分析的视觉模型调用。
- ASR 若启用，按供应商单独计费，不混入模型 token 估算。
- 真实视频生成费用在 T6 接入后单独计算。
- Mock 模式下即使配置单价，也明确提示不会产生供应商费用。

## 5. T2 设计

### 5.1 目标

把人工修改镜头时产生的编辑事件，转化成可持续观察的分析质量信号，帮助团队判断：

- 当前工作窗口内有多少项目、镜头和人工修正。
- 来源判定被人工改写的比例是多少。
- 哪些字段最容易被修正，以及修正涉及多少镜头。
- 分析平均耗时、token 消耗和模型调用次数。
- 最近 30 天修正趋势，以及需要优先排查的项目。

指标用于产品改进，不宣称模型真实准确率，也不作为法律取证结论。

### 5.2 API

`GET /api/insights/quality?days=30`

`days` 支持 `7..90`，默认 `30`。响应包含：

- `summary`：项目数、镜头数、编辑事件、修正镜头、来源修正、来源准确率、修正率、分析次数、平均耗时、token 和模型调用次数。
- `fields`：各字段的修正次数、涉及镜头数和修正率，按次数降序。
- `trend`：窗口内逐日编辑事件、字段修正、来源修正和修正镜头。
- `projects`：窗口内最多 10 个活跃项目的质量明细。
- `suggestions`：由当前样本自动生成的可操作建议。

### 5.3 统计口径

- 项目在窗口内创建、完成分析或发生编辑事件，即视为活跃项目。
- 来源准确率按 `1 - 来源修正镜头数 / 活跃镜头数` 计算。
- 没有人工修正样本时，来源准确率返回 `null`，前端显示 `—`，不将无样本误报为 100%。
- 趋势覆盖窗口内每一天，无事件的日期保留零点。
- 编辑事件来源包括镜头属性修改和基于镜头的版本重建。

### 5.4 边界

- 当前只统计人工编辑事件，不包含用户停留时长、导出转化率等行为分析。
- 项目明细最多展示 10 个项目，完整审计可继续通过编辑事件接口查询。
- 统计窗口过长会降低近期问题可见度，因此限制为 90 天。
- 团队维度、角色筛选和跨用户对比依赖 T11 认证与协作模型。

## 7. T3 设计

### 7.1 目标

在提示词方案工作台内补齐两个高频快捷操作：

- 从版本历史直接选择 A/B 两个快照，查看结构化差异。
- 为分享链接生成可直接扫码打开的二维码，减少复制和二次转发。

不新增生成流程，不改变现有版本快照、分享权限和过期规则。

### 7.2 版本 A/B 对比

`GET /api/prompt-projects/{project_id}/versions/compare?left_id=...&right_id=...`

响应包含：

- `left`、`right`：版本号、来源、标题、创建时间和镜头数。
- `summary`：新增、删除、修改、未变化镜头数，字段变更总量和时长差。
- `field_totals`：发生变化的字段及次数，如 Prompt、运镜、光线。
- `shots`：按镜头序号对齐的差异；每镜标出 `added`、`removed`、`modified` 或 `unchanged`，并列出字段修改前后值。
- `plan_changes`、`brief_changes`、`entity_changes`：方案级、Brief 和 Entity Bible 的变化项。

对比只读，不创建新版本，不修改当前方案。

### 7.3 分享二维码

`GET /api/prompt-projects/{project_id}/shares/{share_id}/qr.svg`

- 使用现有分享 token 生成 SVG 二维码。
- 扫码目标由当前请求的基础地址和 `/share/{token}` 组成，自动适配本机、测试域名和正式域名。
- 使用项目内 QR 编码能力，不调用第三方二维码服务，不上传分享 token。
- 分享的只读/可评论权限、有效期和撤销状态仍由现有分享接口负责。

### 7.4 前端交互

- “方案版本”区域加载后，自动把最近两个版本填入 A/B 选择器。
- 点击“对比版本”后展示概览指标、变化字段和逐镜差异。
- 有差异的镜头默认保留在列表中，可展开查看修改前后值。
- 每条有效分享链接增加“二维码”按钮，展开后显示二维码、链接和复制操作。
- 保持现有明暗风格切换和移动端布局。

### 7.5 边界

- A/B 对比只比较同项目内的版本，不允许跨项目读取版本。
- 同一版本不能与自身对比，返回明确的 `400` 提示。
- 历史快照结构损坏时返回 `409`，不尝试猜测或修复数据。
- 二维码只包含分享 URL，不包含项目内容；分享撤销后扫码仍会看到失效页面。
- 当前不提供团队级访问审计和二维码下载水印，相关能力归入 T11。

### 7.6 验收标准

- 可对比同项目任意两个版本，并正确识别新增、删除、修改和未变化镜头。
- 不在同项目中的版本或失效版本返回 `404`，同一版本返回 `400`。
- 对比结果展示字段变化、镜头级前后值和方案级变化。
- 有效分享可生成可访问的 SVG 二维码，接口不依赖外网。
- 二维码内容使用当前浏览器访问域名。
- 后端测试、前端语法检查和浏览器点击验证全部通过。

## 9. T4 设计

### 9.1 目标

让镜头模板从“固定镜头片段”升级为可复用资产：

- 保存模板时可编辑 Prompt 模板，并保留 `{{placeholder}}`。
- 套用模板时按目标镜头和方案上下文替换占位符。
- 支持分类、多标签和关键词组合筛选。
- 对无法替换的占位符给出明确提示，不静默生成带占位符的 Prompt。

### 9.2 占位符

Prompt 及文本字段支持 `{{key}}` 语法。可用值包括：

- 镜头上下文：`index`、`shot_type`、`camera_movement`、`subject`、`action`、`scene`、`lighting`、`transition`、`duration`、`prompt`、`negative_prompt`、`remake_notes`、`color_palette`。
- 方案上下文：`title`、`summary`、`target_model`、`language`、`duration_s`、`aspect_ratio`、`global_style`。

替换规则：

- 已知且有值：写入目标值。
- 已知但为空：替换为空字符串，并在方案 warnings 中提示。
- 未知 key：保留原占位符，并在方案 warnings 中提示，避免用户误以为已替换。
- 同一模板套用到多个镜头时，每个镜头使用各自的目标上下文独立替换。
- 占位符替换发生在字段写入前，目标镜头上下文取套用前的快照，避免字段之间的顺序影响结果。

### 9.3 标签与筛选

- `GET /api/shot-templates` 增加 `tags` 查询参数，支持重复参数或逗号分隔；多个标签采用 AND 语义。
- 新增 `GET /api/shot-templates/facets`，返回分类和标签的可用值及数量。
- 搜索范围补充 Prompt 模板与 Negative Prompt。
- 前端提供分类下拉、标签 chips 和关键词搜索，筛选条件组合后请求后端。

### 9.4 用户隔离边界

当前系统只有全局 HTTP Basic Auth，没有 User、Team 或 Role 数据模型，无法可靠区分模板所有者。本任务不采用浏览器自报用户名或可伪造请求头做“伪隔离”。

模板隔离仍归入 T11：

- 新增用户和团队模型。
- 模板写入 `owner_id` / `team_id`。
- 列表、修改和套用统一校验所有权。

T4 完成占位符和筛选后，可先满足单工作区使用；T11 再补数据级隔离。

### 9.5 验收标准

- 保存模板时可提交自定义 `prompt_template`。
- 套用时 `{{subject}}`、`{{scene}}`、`{{lighting}}` 等按目标镜头替换。
- 未知占位符保留并写入 warnings；空值占位符替换为空并提示。
- 分类、多标签和搜索可组合筛选，facets 数量正确。
- 前端可编辑 Prompt 模板、插入占位符并按分类/标签筛选。
- 全量测试、静态检查和浏览器点击验证通过。

## 11. T5 设计

### 11.1 目标

为已完成分析的视频项目提供可视化时间轴，让用户可以直接修正自动分镜：

- 查看每个镜头的起止时间、时长和关键帧。
- 拖动相邻镜头边界，保持时间轴无空隙。
- 在指定时间拆分镜头。
- 合并两个相邻镜头。
- 对单个镜头重新抽帧并重新分析。
- 修改后自动重建 Recipe，并提示关联提示词方案的镜头映射已变化。

### 11.2 时间轴一致性

- 镜头按 `index` 排序，时间区间必须首尾连续。
- 拖动边界使用左镜头的 `shot_id` 和分界时间 `boundary_s`；后端同步更新左镜头 `end_s` 与右镜头 `start_s`。
- 任一侧修改后时长不得小于 `MIN_SHOT_SECONDS`，默认 `0.8s`。
- 拆分点必须位于镜头内部，且距离两端都不小于 `MIN_SHOT_SECONDS`。
- 合并只允许两个相邻镜头；保留左镜头 ID，合并时间区间与转录文本，并重排全部镜头序号。
- 拆分和合并后都重新编号为连续的 `1..N`，不允许序号空洞。

### 11.3 异步重分析

结构编辑在请求内完成并返回 `202`，随后创建项目级 `Job`：

1. 更新项目为 `queued`，前端通过现有 `/api/jobs/{job_id}/events` SSE 获取状态。
2. 后台读取视频元数据；若启用 ASR，则重新转写并按最新时间区间对齐转录。
3. 对受影响镜头按中点重新抽取关键帧，文件名使用稳定的 `shot_{shot_id}.jpg`。
4. 调用现有视觉分析能力，仅重分析受影响镜头。
5. 重建 `video.md` / `video.json`，更新任务与项目状态。
6. 失败时保留已保存的时间轴结构，返回可重试的单镜重分析入口。

### 11.4 提示词映射失效

时间轴变化后，已有 `PromptProject` 中的 `source_shot_index` 可能不再对应最新镜头。T5 不静默重算或覆盖提示词版本，而是：

- 向所有关联提示词方案的 `plan.warnings` 追加“参考视频时间轴已变化，请重新生成或校准镜头映射”。
- 保留原版本快照、导出内容和人工编辑结果。
- 用户可主动重新生成提示词方案，或继续只读查看旧版本。

### 11.5 API


`POST /api/projects/{project_id}/shots/{shot_id}/split`

```json

```

`POST /api/projects/{project_id}/shots/merge`

```json
{"shot_ids": [3, 4]}
```

`POST /api/projects/{project_id}/shots/{shot_id}/reanalyze`

四个操作均返回 `job_id`、`action`、`affected_shot_ids` 和被标记的提示词方案数量。项目正在分析或已有活动任务时返回 `409`；容量不足返回 `503`；参数越界返回 `422`。

### 11.6 前端交互

- 在分析媒体区与镜头卡片之间增加时间轴。
- 每个镜头段按时长比例布局，显示序号、关键帧、起止时间与当前选中状态。
- 镜头之间的边界显示可拖拽手柄；拖动时实时预览相邻段宽度，释放后提交。
- 点击镜头段会选中镜头，并把视频播放位置跳到该镜头起点。
- 选中镜头后显示操作栏：拆分点输入、拆分、与下一镜合并、重抽帧并重分析。
- 分析运行期间禁用结构编辑按钮和拖拽。
- 指针拖拽与键盘方向键都支持边界调整，移动端保留可点击的镜头段和操作按钮。

### 11.7 验收标准

- 可拖动相邻镜头边界，左右镜头时间同步更新且不重叠、不留空。
- 可在合法位置拆分镜头，序号和时间连续。
- 可合并两个相邻镜头，保留左镜头 ID 并重排序号。
- 可只重抽并重分析一个镜头，Recipe 自动重建。
- 结构变化会使关联提示词方案出现映射失效 warning，原版本不被覆盖。
- 并发任务、越界参数和容量不足返回明确错误。
- 后端测试、前端语法检查、全量回归和浏览器点击验证通过。
