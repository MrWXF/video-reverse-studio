# 项目设计：ReelReverse 视频逆向工作台

> 版本：v0.1 设计稿  
> 日期：2026-11-21

## 1. 背景与机会

短视频、广告和 AI 生成视频的产量在快速增长，但"拆片"仍然高度依赖人工：逐帧暂停、截图、记笔记、猜运镜、反推提示词。一条 10 分钟的视频，熟练编导也要 1–2 小时才能整理出可用结构。

与此同时，多模态模型已经能同时理解画面和文字，单次调用就能输出景别、运镜、主体、风格和复刻提示词。缺的不是模型能力，而是**把模型能力组织成稳定工作流的工程**。

机会点：把"看视频"变成一份**可执行、可复用、可对比的制作配方**。

## 2. 目标用户与场景

| 用户 | 典型场景 | 核心诉求 |
|------|----------|----------|
| 短视频编导 | 拆解爆款视频的节奏与镜头结构 | 快速拿到分镜表 |
| AI 视频创作者 | 反推某条素材的提示词和镜头语言 | 直接可用的 prompt |
| 广告 / 影视前期 | 分析参考片的视觉方案 | 结构化拉片报告 |
| 品牌内容团队 | 拆解竞品素材，形成内部模板 | 可沉淀的素材库 |
| 学习者 / 求职者 | 系统学习镜头语言，做作品集 | 可展示的分析成果 |

核心 JTBD（Jobs To Be Done）：

> 我看到一条好视频，想在一小时内做出**结构相同、风格接近**的版本。

## 3. 问题定义

1. **结构不可见**：视频是连续流，镜头边界、节奏、信息密度都藏在时间里。
2. **复刻不可执行**：一句"高级感"无法指导拍摄或生成。
3. **来源不可判断**：实拍、AI 生成、代码生成混在一起，素材溯源困难。
4. **经验不可复用**：拉片结果散落在聊天记录和截图里，无法检索和对比。

## 4. 产品定位

**一句话**：上传任意视频，输出一份可复刻的 `VIDEO.md` 制作配方。

差异化：

- 输出的不是"总结"，而是**逐镜可执行的配方**
- 每个镜头都有结构化字段 + 英文复刻提示词
- 增加**来源三分类**：实拍 / AI 生成 / 代码生成
- 支持私有部署，素材不出内网
- 无 API Key 也能用 Mock 模式跑通全流程，方便演示和测试

## 5. MVP 范围

### Must（v0.1 必做）

- 上传本地视频（MP4 / MOV / WebM / MKV，≤500MB）
- 自动探测时长、分辨率、帧率
- 场景检测分镜 + 关键帧抽取
- 逐镜视觉分析：景别、运镜、主体、场景、风格、光线、色板、来源、置信度、证据、复刻提示词
- 生成 `VIDEO.md` 和 `video.json`
- Web 工作台：上传、进度、镜头卡片、配方预览、下载
- Mock 模式与真实 LLM 模式可切换

### Should（v0.1 尽量做）

- 音频转写，并把台词对齐到镜头
- 节奏指标：平均镜头时长、每分钟剪辑数、快慢判定
- 失败重试与错误可见
- token 消耗统计

### Could（后续）

- 批量对比、相似镜头检索
- 自动生成复刻任务并调用视频生成模型
- 团队空间、权限、审核流
- 来源判定评测集与准确率看板

## 6. 非目标

- 不做视频下载、搬运、去水印
- 不做视频生成或渲染（v0.1 只输出配方）
- 不做版权归属判定
- 不做模型训练 / 微调
- 不做多人实时协作

## 7. 用户流程

```mermaid
flowchart LR
    A[上传视频] --> B[创建项目与任务]
    B --> C[探测元数据]
    C --> D[场景检测分镜]
    D --> E[抽取关键帧]
    E --> F[音频转写 可选]
    F --> G[逐镜视觉分析]
    G --> H[融合与节奏分析]
    H --> I[生成 VIDEO.md]
    I --> J[预览 / 下载 / 再分析]
```

## 8. 功能清单

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| F1 | 视频上传 | 类型、大小、空文件校验 | P0 |
| F2 | 元数据探测 | 时长、分辨率、帧率 | P0 |
| F3 | 自动分镜 | ffmpeg 场景分数 + 最短镜头合并 + 上限保护 | P0 |
| F4 | 关键帧抽取 | 每镜取中点帧，缩放到 768px | P0 |
| F5 | 音频转写 | OpenAI 兼容 ASR，按时间对齐 | P1 |
| F6 | 逐镜分析 | LangChain + Vision LLM，结构化输出 | P0 |
| F7 | 来源判定 | filmed / ai_generated / code_generated | P0 |
| F8 | 配方生成 | Markdown + JSON 双格式 | P0 |
| F9 | 工作台 | 列表、详情、轮询进度、预览 | P0 |
| F10 | 下载导出 | 下载 VIDEO.md / JSON | P0 |
| F11 | Mock 模式 | 无 Key 可演示、可测试 | P0 |
| F12 | 健康检查 | LLM / ffmpeg 可用性 | P1 |

## 9. 输出物规格：VIDEO.md

### 9.1 Frontmatter

```yaml
title: "视频标题"
source: "source.mp4"
duration_s: 30.0
resolution: "1920x1080"
fps: 30.0
shots: 12
cuts_per_minute: 24.0
pacing: "fast"
generated_at: "2026-11-21T10:00:00+00:00"
generator: "reelreverse/0.1"
```

### 9.2 镜头表

| 字段 | 含义 |
|------|------|
| index | 镜头序号 |
| start_s / end_s | 起止时间 |
| shot_type | 景别 |
| camera_movement | 运镜 |
| subject | 画面主体 |
| origin | 来源判定 |
| confidence | 置信度 0–1 |

### 9.3 逐镜块

每个镜头包含：视觉描述、光线与色板、来源证据、复刻提示词、复刻注意事项、对齐后的台词。

### 9.4 质量要求

- 分镜边界可人工复核
- 提示词必须是英文、可执行的描述，而不是抽象的"高级感"
- 来源判定必须带证据，不能只给结论
- 文件本身可被其他工具解析（YAML + Markdown 表格）

## 10. 成功指标

| 指标 | 目标 | 测量方式 |
|------|------|----------|
| 处理时延 | 10 分钟视频 ≤ 5 分钟 | 任务耗时统计 |
| 分镜可用率 | 人工抽检 ≥ 80% 边界正确 | 50 条视频标注 |
| 来源判定准确率 | 三分类 ≥ 75% | 100 镜头自建评测集 |
| 单视频成本 | ≤ ¥1（20 镜头） | token 统计 |
| 首次成功体验 | 无 Key 也能看到完整结果 | Mock 模式验收 |

| 方案 | 价格 | 权益 |
|------|------|------|

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 快切、转场特效导致分镜不准 | 镜头表可用性下降 | 场景阈值可配 + 最短镜头合并 + 人工修正入口 |
| 运镜判断主观 | 分析结果争议 | 输出置信度与证据，明确"模型推断" |
| 视觉模型成本高 | 单视频成本失控 | 限制镜头数、关键帧缩放、并发限流、成本看板 |
| 模型不支持图片输入 | 分析失败 | 启动时提示 + 自动降级 Mock |
| 版权与平台合规 | 法律风险 | 只处理用户上传内容，不做下载搬运，明确免责声明 |
| 长视频处理超时 | 任务失败 | 分段处理、任务队列、超时与重试 |

## 13. 迭代路线

- **v0.1（4–6 周）**：分镜 + 逐镜分析 + VIDEO.md + 工作台
- **v0.2（+2 周）**：音频情绪、BGM 节奏、批量对比、镜头相似度
- **v0.3（+3 周）**：对接可灵 / 即梦 / Runway / Veo，生成复刻任务队列
- **v0.4（+3 周）**：团队空间、素材库、权限、审核流
- **v0.5（+2 周）**：评测集、来源判定准确率看板、回归测试
