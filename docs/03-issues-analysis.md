其中的 P0/P1/P2 已经分别对应“逆向项目与提示词关联、镜头编辑与版本、任务控制与交付分享”等已交付能力；本次逐项复查后，真实缺陷已经修复，过时判断和设计取舍已经明确标注。

核对结果分为三类：

- **已修复**：代码、配置或测试已经补齐。
- **已核实非问题**：原报告判断不成立或已经被现有实现满足。
- **已核对设计取舍**：属于单体 MVP 的合理边界，不是当前缺陷；不作为未完成事项。

原报告共 19 项：严重 5 项、中等 8 项、轻微 6 项。当前状态全部为 `[x]`。

## 3. 严重问题

### 3.1 测试覆盖率

**状态：`[x] 已修复`**

原报告写“核心模块完全无测试”已经过时。仓库此前已有融合、提示词生成、提示词路由、P1/P2 功能与安全测试。本次继续补齐真正缺失的部分：

- `tests/test_pipeline.py`：完整流水线、瞬态故障重试、错误脱敏、并发上限。
- `tests/test_vision.py`：Mock 降级、结构化输出、模型失败降级与脱敏。
- `tests/test_hardening.py`：重试、脱敏、上传签名、容量、SSE 限制、请求追踪、API v1 与 OpenAPI。
- `tests/test_db_migration.py`：旧库迁移、迁移版本记录、幂等性。

当前验证结果：`82 passed`。

### 3.2 后台任务错误恢复

**状态：`[x] 已修复`**

新增 `app/services/retry.py`，提供：

- 最大尝试次数；
- 指数退避；
- 可重试异常判断；
- 不可重试错误立即失败。

已接入：

- 视频逆向流水线；
- 提示词生成；
- 视觉模型调用；
- 单镜提示词重生成；
- 成片回测。

默认配置为 3 次尝试、0.8 秒起步、最大 8 秒退避。瞬态网络错误会重试，参数错误、文件不存在、用户取消等不会盲目重试。

### 3.3 并发和资源限制

**状态：`[x] 已修复`**

新增 `app/services/capacity.py`，对逆向分析、提示词生成和成片回测使用统一的活跃任务计数：

- `MAX_ACTIVE_JOBS` 默认 4，最大 32；
- API 预检超限时返回 `503`；
- 后台任务启动时再次原子抢占槽位，避免竞态；
- 任务完成、失败、取消均通过 `finally` 释放；
- 单任务内部 LLM 并发仍由 `LLM_CONCURRENCY` 控制。

当前采用“立即拒绝过载”的边界策略，不引入无界内存队列。Celery/RQ 属于多实例扩展方案，不是当前单体 MVP 的缺陷。

### 3.4 敏感信息泄露

**状态：`[x] 已修复`**

核对结果：

- `.gitignore` 已包含 `.env`，原报告“未忽略”不成立。
- API Key 只从环境变量读取，不写入数据库或 API 响应。
- 新增 `app/services/redaction.py`，统一替换数据目录、项目根目录、用户主目录、API Key、Bearer Token、密码字段。
- 任务错误、提示词错误、成片回测错误和 vision 降级证据均使用脱敏结果。
- JSON 日志同样对消息和堆栈做脱敏。

生产环境仍建议把 `.env` 替换为平台 Secret Manager；这是部署实践，不是应用代码缺陷。

### 3.5 数据库迁移

**状态：`[x] 已修复`**

SQLite 初始化改为版本化迁移：

- 新增 `schema_migrations(version, name, applied_at)`；
- 迁移按版本只执行一次；
- 旧数据库保留原有数据；
- 列添加逻辑保持幂等；
- 空数据库不会因缺少业务表而报错。

本次没有引入 Alembic，原因是当前默认单库 SQLite、迁移规模较小；版本表和幂等迁移已经满足可追踪与可重复执行要求。未来切换到 PostgreSQL 多团队协作时再引入 Alembic 更合适。

## 4. 中等问题

### 4.1 日志规范

**状态：`[x] 已修复`**

- 启用 JSON 行日志；
- 每条日志包含时间、级别、logger、消息、`request_id`；
- 支持客户端传入 `X-Request-ID`，否则生成 UUID；
- 响应统一返回 `X-Request-ID`；
- 请求日志包含方法和耗时；
- 后台任务继承创建请求的追踪 ID，并写入任务 metrics；
- 未捕获异常返回脱敏后的 500 JSON，不暴露堆栈。

### 4.2 提示词与模板常量

**状态：`[x] 已修复`**

景别、运镜、光线、转场、色板、Mock 主体与风格迁移到 `app/prompts/catalog.json`。

加载器行为：

- 默认读取内置词表；
- 可通过 `PROMPT_CATALOG_FILE` 指向自定义文件；
- 基于文件 mtime 检测变化，无需重启即可重新加载；
- 自定义文件缺字段或不可用时记录警告并回退内置词表。

### 4.3 前端模块化

**状态：`[x] 已完成共享层拆分`**

新增 `app/static/shared.js`，统一提供：

- DOM 选择器；
- HTML 转义；
- Toast；
- JSON API 请求；
- 剪贴板复制；
- 数字与时码格式化。

`app.js` 与 `prompt.js` 已改为从 `window.ReelReverse` 取用共享能力，删除了重复实现。

保留原生 JavaScript 单页结构是有意的产品取舍：当前没有构建链、没有前端路由、部署简单，直接拆成 ES Module 反而会增加发布复杂度。后续若继续扩展编辑器，再按“逆向工作区 / 提示词工作区 / 交付工作区”拆成构建型前端。

### 4.4 API 版本管理

**状态：`[x] 已修复`**

- `/api/v1/*` 为正式版本入口；
- `/api/*` 保留为兼容入口；
- 两者共享同一套 v1 语义；
- 所有响应包含 `X-API-Version: v1`；
- OpenAPI 同时展示两个入口，v1 operationId 带 `_v1` 后缀；
- 后续破坏性变更可新增 `/api/v2`，不强制现有前端迁移。

### 4.5 Mock 模式

**状态：`[x] 已修复`**

- 台词参与哈希种子，改变台词会改变镜头判断与 Prompt；
- 台词写入证据与 Prompt 上下文；
- `MOCK_SCENARIO=success`：正常返回；
- `MOCK_SCENARIO=fail`：模拟整体失败；
- `MOCK_SCENARIO=fail_shot` 与 `MOCK_FAIL_SHOT=N`：模拟指定镜头失败；
- `MOCK_SCENARIO=slow`：增加延迟，便于测试取消与 SSE。

### 4.6 请求验证与清理

**状态：`[x] 已修复`**

路径穿越判断已核实为不成立：上传文件使用固定项目目录和固定目标名 `source{suffix}` 或 `delivery{suffix}`，用户文件名不会进入保存路径。

本次补充真实缺口：

- 校验 MP4/MOV/M4V 的 `ftyp` 容器头；
- 校验 WebM/MKV 的 EBML 头；
- 校验 AVI 的 `RIFF/AVI` 头；
- 扩展名与内容不匹配返回 400；
- 客户端文件名移除目录、控制字符和首尾危险字符；
- 项目标题统一清理并限制长度；
- 上传大小继续由 `MAX_UPLOAD_MB` 限制；
- 超限返回 413。

### 4.7 缓存机制

**状态：`[x] 已处理`**

已实现：

- `/static/*` 返回 `Cache-Control: public, max-age=3600, stale-while-revalidate=86400`；
- 静态文件继续使用 Starlette 的文件响应与条件请求能力。

没有引入 Redis 或 LLM 响应缓存，原因：

- 视频分析包含关键帧、台词和版本，缓存键与失效策略复杂；
- 提示词生成是创作型输出，默认不应静默复用旧结果；
- 当前部署以单机私有化为主，先保证可观测性和成本可见性更合理。

“重复分析缓存”属于产品级优化，不是当前质量缺陷。

### 4.8 SSE 连接管理

**状态：`[x] 已修复`**

- 每 15 秒发送 `heartbeat` 事件；
- 单连接最长 900 秒，超时返回结构化错误；
- 最大并发连接数默认 32；
- 客户端断开立即退出；
- 正常结束、异常或断开均在 `finally` 释放连接计数。
