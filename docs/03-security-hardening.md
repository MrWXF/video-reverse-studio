# 安全加固设计：受控媒体访问与基础认证

> 版本：v0.1  
> 范围：第一批安全闭环  
> 状态：已实现，测试通过

## 1. 背景

当前项目把整个 `data/` 目录挂载到 `/files`，而 `data/` 同时包含：

- `app.db`：项目、镜头、任务和提示词数据
- `projects/{id}/source.*`：用户上传的原始视频
- `projects/{id}/frames/*`：关键帧
- `projects/{id}/output/*`：`VIDEO.md` 与 `video.json`

在本地演示环境中这很方便，但公开部署后会导致数据库和所有项目素材被直接下载。当前 API 也没有身份认证，知道项目 ID 即可读取或删除项目。

实测问题：

- `/files/app.db` 返回 HTTP 200
- `/files/.git-meta/config` 返回 HTTP 200
- `/api/projects` 无需认证即可列出全部项目

## 2. 目标与非目标

### 目标

1. 不再通过静态目录暴露整个 `data/`。
2. 只允许通过项目级接口读取视频和关键帧。
3. 所有业务接口支持可选 HTTP Basic 认证。
4. 认证开启后，除健康检查外的页面、API、文档和静态资源都需要认证。
5. 保持本地零配置模式可启动，不强制现有开发流程立即配置密码。
6. 增加覆盖认证、文件访问和 URL 生成的安全测试。

### 非目标

- 不实现完整用户体系、OAuth、RBAC 或项目级成员权限。
- 不实现对象存储和签名 URL。
- 不实现登录页和 Session 管理。
- 不修改现有数据库表结构。

## 3. 威胁模型

### 需要防护的路径

- 直接访问 `/files/app.db` 获取业务数据。
- 通过 `/files/projects/{id}/source.mp4` 批量下载素材。
- 通过 `/api/projects/{id}` 枚举项目并读取分析结果。
- 通过 `/api/projects/{id}` 删除他人项目。
- 构造路径穿越，读取项目目录之外的文件。

### 信任边界

- 反向代理负责 TLS、请求体大小和基础网络访问控制。
- 应用负责基础认证、项目范围校验和文件路径约束。
- 项目 ID 不再被视为访问凭证。

## 4. 认证设计

### 配置

新增环境变量：

```env
APP_USERNAME=admin
APP_PASSWORD=
```

- `APP_PASSWORD` 为空时，认证关闭，保持本地开发体验。
- `APP_PASSWORD` 非空时，所有请求必须携带 HTTP Basic 凭证。
- `/healthz` 始终公开，供容器和反向代理探活。
- 生产环境必须通过 HTTPS 访问，避免 Basic 凭证明文传输。

### 行为

| 场景 | 结果 |
|------|------|
| 未配置密码 | 直接放行 |
| 已配置密码、无 Authorization | `401` + `WWW-Authenticate: Basic` |
| 已配置密码、用户名或密码错误 | `401` |
| 已配置密码、凭证正确 | 放行 |
| 访问 `/healthz` | 始终放行 |

用户名和密码使用常量时间比较，避免明显的时间侧信道。

## 5. 媒体访问设计

### 接口变更

移除：

```text
GET /files/*
```

新增：

```text
GET /api/projects/{project_id}/video
GET /api/projects/{project_id}/shots/{shot_id}/keyframe
```

序列化字段同步调整：

```json
{
  video_url: /api/projects/{project_id}/video,
  keyframe_url: /api/projects/{project_id}/shots/{shot_id}/keyframe
}
```

### 路径校验

读取文件前必须同时满足：

1. 项目存在。
2. 文件解析后的真实路径位于 `data/projects/{project_id}` 内。
3. 目标是普通文件。

任何条件不满足都返回 `404`，不暴露绝对路径或文件系统信息。

### 兼容性

- 前端只使用后端返回的 `video_url` 和 `keyframe_url`，因此无需硬编码 `/files`。
- 旧的 `/files/...` 链接会失效，这是有意的安全破坏性变更。
- `VIDEO.md`、JSON 下载接口保持不变，但同样受认证保护。

## 6. 测试计划

### 单元测试

- Basic 认证头解析正确。
- 错误凭证和缺失凭证被拒绝。
- 项目媒体路径不允许跳出项目目录。
- 序列化结果返回新的项目级媒体 URL。

### 集成测试

- 认证关闭时，首页可访问。
- 认证开启时，未认证首页返回 `401`。
- 正确 Basic 凭证可访问首页。
- `/healthz` 在认证开启时仍返回 `200`。
- `/files/app.db` 返回 `404`。
- 视频和关键帧接口在认证开启时要求认证。
- 已认证且项目存在时，视频和关键帧接口返回 `200`。

### 回归测试

- 现有 `pytest` 全部通过。
- 页面上传、视频播放、镜头关键帧和配方下载继续工作。
